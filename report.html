İZLEK Bench

Valid State Updates and Source Attribution in Turkish Dialogues

CMPE / EEEN 566 · Research report · Dataset version 1.0.0 · 23 November 2026

Semi KIRCI · CMPE / EEEN 566

Abstract

İZLEK Bench evaluates whether large language models can identify valid updates in Turkish task dialogues and attribute the resulting field values to the correct source messages. A proposed update may be approved, rejected, restricted to one record, conditioned on an event, delegated to another speaker, or limited in duration. The task therefore requires both state reconstruction and explicit source attribution.

The dataset contains 72 cases organized into 36 contrastive pairs across six task families. Sixty cases are reserved for testing and twelve for development. Each pair differs in exactly one message. A deterministic evaluator checks six field values and six source identifiers per response. The accompanying public platform supports dataset inspection, response submission, scoring, and comparison of uploaded model runs.

Three models were evaluated on the same 60 test cases through Groq with one generation per case. Joint exact accuracy was 90.00% for GPT-OSS 120B, 88.33% for Qwen 3.8 27B, and 46.67% for GPT-OSS 20B. The first two models differed by one correct case. Selective rollback exposed a common error in interpreting a negated revocation. The 20B score was additionally affected by source-identifier format failures and output truncation. These results characterize performance under the specified strict output contract, not general Turkish proficiency.

Research question and hypotheses

Research question: Can LLMs apply only authorized, in-scope, currently valid updates in Turkish dialogues, preserve unaffected fields, and identify the message that established each final value?

H1: For at least two models, state exact accuracy will exceed joint exact accuracy by at least 10 percentage points. H2: For at least two models, case-level joint exact accuracy will exceed pair accuracy by at least 10 percentage points. H3: Selective rollback and temporary-update tasks will yield a higher proportion of source errors than endorsement tasks. These hypotheses were recorded before the test runs; their outcomes are discussed below. They were not externally preregistered.

Contribution and language

The contribution is an original, narrowly scoped task design that jointly measures authorization, scope, validity, and attribution in Turkish dialogues. The interface and report are in English. Experimental prompts remain in Turkish because Turkish language understanding is the target construct. English glosses are provided only for exposition and are not substituted for the original prompts during evaluation.

Related Work and Originality

Instruction following, conversational correction, and state updating are established research areas. Describing the project solely as a Turkish multi-turn instruction benchmark would therefore be insufficient to establish originality. The following comparison defines the intended contribution and its limits.

Verifiable and multi-turn instructions

IFEval [1] evaluates automatically verifiable instructions. FollowBench [2] studies multiple types of constraints at increasing levels of difficulty. Multi-IF [3] extends instruction-following evaluation across languages and turns. İZLEK also uses deterministic scoring, but targets the validity and provenance of updates rather than output-length or stylistic constraints.

Corrections and state updates

LongMemEval [4] includes knowledge updates among the capabilities tested in long-term conversational memory. MultiTurnInstruct [5] studies interdependent and dynamic instructions, including conflict resolution, and is especially relevant to this project. RefuteBench [6] examines compliance with user corrections and their persistence. İZLEK distinguishes valid corrections from proposals that should not be applied; accepting every recent change is not sufficient for success.

Authority and controlled state tracking

Instruction Hierarchy [7] studies conflicts between instructions with different trust levels. Ai2 StateBench [8] evaluates changing states in controlled tasks. Consequently, source trust, state reconstruction, and contrastive task construction are not individually novel. İZLEK investigates a specific intersection of these constructs in short Turkish dialogues, with an explicit source policy and field-level verification.

Scope of the originality claim

The claim concerns the original scenarios and their joint evaluation design: six semantic contrasts, paired cases differing in one message, preservation of unaffected fields, and verification of both values and assignment sources. Questions from existing benchmarks were not translated or lightly modified. However, this literature review is not exhaustive, and it does not establish a first-of-its-kind claim.

The assignment requires a research question not already covered by well-known benchmarks. The narrow combination above provides a defensible argument, but satisfying that requirement cannot be guaranteed merely by creating new wording or increasing the number of instances. Shared templates and overlap with prior work should be considered explicitly when assessing originality.

The task is not a security attack evaluation or a direct test of API role hierarchy. Speaker labels such as Yönetici (Manager) and Asistan (Assistant) are fictional transcript elements within a single user message.

Dataset and Task Design

Each case contains two events with three fields: yer (location), saat (time), and kanal (notification channel). The first message establishes the initial records. Subsequent messages introduce an independent channel update, a target intervention, and an unauthorized reminder. The output contains durum (state) and kaynak (source) objects, with six values and six source identifiers.

Generation and splitting

Six contexts are used: workshops, seminars, laboratory sessions, rehearsals, project meetings, and excursions. Workshop cases form the development split; the remaining contexts form the test split. Both variants of a pair remain in the same split. Exactly one message changes within each pair, and A/B labels do not consistently encode the direction of the update.

The dataset is synthetic and AI-assisted. Six task templates authored for this project are instantiated deterministically with context-specific event names, locations, and times. The generator records expected outputs and operation traces. The tests also include manually specified reference checks. Independent human annotation review has not been completed. Context separation does not establish generalization to unseen templates because templates are shared across splits.

Illustrative case

The Seramik event initially takes place in Stüdyo 1, established by m1. An assistant relays a draft proposal to use Stüdyo 3 in m3. If the manager approves the proposal in m4, the correct location becomes Stüdyo 3 with source m4. If approval is withheld, Stüdyo 1 and source m1 remain valid. An independent notification-channel update for the Fotoğraf event must be preserved in both variants.

Versioning and integrity

benchmark.json contains annotations and traces; prompts.jsonl contains inference inputs only. A manifest records the SHA-256 digest of the annotated dataset. This English presentation revision leaves experimental prompts, labels, and the dataset digest unchanged. Any future change to the experimental material requires a new dataset version.

Scoring and Experimental Protocol

Metrics

The primary metric is joint exact accuracy. A case receives one point only if all six values and all six sources are correct; otherwise it receives zero. The test score is 100 × correct cases / 60. Value accuracy is the number of correct field values divided by 360; source accuracy uses the same denominator. State exact accuracy requires all six values to be correct without considering source identifiers.

Pair accuracy is the percentage of the 30 test pairs for which both variants are jointly exact. Coverage counts non-empty submitted response contents, not successful HTTP transactions. Empty responses receive zero credit. Invalid JSON or any response-contract violation, including decorated source identifiers, results in zero credit for the entire case. All test metrics retain the denominator of 60 cases.

Response and attribution contract

Responses must contain JSON only, with exactly the prescribed objects and string fields. The evaluator rejects explanatory text, Markdown fences, duplicate or additional keys, missing fields, non-string values, and source strings that do not exactly match a transcript message identifier after NFC and whitespace normalization. The Turkish prompt requests message identities and exact transcription, but supplies no worked JSON example and does not explicitly enumerate every parser rejection. This strict interpretation is a construct-validity limitation.

A source identifies the message that established the currently valid value. Endorsement cites the approval message. When a condition is satisfied, the conditional instruction is the source. Rollback and expiry restore the earlier value and its original assignment source. A delegation message does not establish a field value unless it also assigns that value.

Controlled model comparison

GPT-OSS 20B (openai/gpt-oss-20b), GPT-OSS 120B (openai/gpt-oss-120b), and Qwen 3.8 27B (qwen/qwen3.8-27b) received the same 60 test prompts through Groq on 23 November 2026. Provider-returned identifiers matched requested identifiers. Each case used one independent user message, temperature 0, max_completion_tokens 4096, no tools, and no JSON-mode. One repetition was executed. The order was shuffled with seed 566; the prompt SHA-256 matched the preserved input file for every run.

Five development responses from GPT-OSS 20B were retained as connection checks; a complete three-model development evaluation was not conducted. All 180 test API calls returned responses. Test data, prompts, labels, and scoring rules were preserved during analysis, and incorrect responses were not selectively regenerated. Model identifiers are provider names rather than immutable checkpoint digests. Equal completion limits do not imply equal effective reasoning or output budgets across models.

Uncertainty

A 95% interval for joint exact accuracy is estimated using 2,000 pair-level bootstrap resamples within each family, with seed 566. The two variants are not treated as independent samples. Shared templates limit interpretation; these exploratory intervals do not quantify stochastic variability across repeated model generations.

Representative failure mechanisms

In IZ-42-B, m5 says “m3 mesajındaki yer değişikliğini geri alma” (do not undo the location change in m3). All three models nevertheless returned Salon A / m1 instead of Salon C / m3. The same negated-rollback error occurred in all five contexts for 120B and Qwen. The wording tests Turkish negative imperative morphology; these outputs alone cannot establish the internal cause.

GPT-OSS 20B had 23 source-format failures, typically writing “[m4] Yönetici” rather than “m4”. Two additional outputs ended with finish_reason=length: IZ-12-A contained truncated JSON and IZ-16-A was empty. These are distinct from access failures. Of the 35 contract-valid cases, 28 were jointly correct; this conditional subset is not directly comparable with the other models’ full-set scores.

Interpretation and Limitations

Hypothesis outcomes

H1 was not supported: state-exact minus joint-exact gaps were 3.33, 1.67, and 0 percentage points for 20B, 120B, and Qwen, all below 10. H2 was supported descriptively for 20B (30 points) and Qwen (11.66 points), but not 120B (6.67 points). H3 was only partially supported: 120B and Qwen had more source-field errors in rollback than endorsement, but temporary-update errors exceeded endorsement only for Qwen. Format failures confound the 20B comparison. No confirmatory significance tests were specified.

Baselines and practical interpretation

The deterministic “preserve initial state” baseline obtained 69.44% value accuracy and 0% joint exact; “apply first explicit update” obtained 86.11% value accuracy, 33.33% joint exact, and 0% pair exact. High field averages can reflect unchanged fields rather than successful contrast resolution. All three LLMs exceeded the second baseline in joint exact, although strict format failures reduced 20B field scores below the baselines. Neither baseline counts as an LLM.

Threats to validity

The dataset is short-context, synthetic, AI-assisted, and generated from six shared templates. The 60 cases are not 60 independent task designs. The negative imperative “geri alma” and the conditional wording in permanent-update cases warrant independent Turkish-language review. Such review has not been completed; the labels have not been changed after observing results.

A strict identifier parser conflates source-selection ability with rendering conventions. In particular, decorated identifiers may communicate a recognizable source while still violating the evaluated contract. The unchanged primary metric should be read as end-to-end contract compliance. A future, separately specified study could add worked examples, structured output, or a secondary normalization analysis and rerun every model consistently.

Only one generation per case was collected. Temperature zero does not ensure determinism. Provider checkpoint revisions, reasoning defaults, and output-budget allocation are not fully controlled. The two GPT-OSS sizes share a family; this is a three-model comparison, not three independent model families. Public answer keys create contamination risk for future evaluations.

Conclusion

Under this fixed protocol, 120B and Qwen handled most authorization, scope, condition, and delegation contrasts, but both failed systematically on retained-update variants of selective rollback. The 20B result shows that response-contract adherence can dominate an otherwise semantic benchmark. The study supports paired evaluation and explicit source reporting while limiting claims to these templates, these recorded model endpoints, and this generation setting.

Reproducibility and References

The release contains the 72-case annotated dataset, prompts-only inputs, source code, shared browser/CLI evaluator, three preserved test response files, scored results, and this report. The static interface displays the recorded study alongside browser-local uploads. Published records are not independently audited. API secrets and provider request identifiers are excluded from the release.

Recompute the study with: node scripts/publish_results.mjs results/published. To score one preserved run, use node scripts/score.mjs results/published/RUN.json results/score.json test. The benchmark manifest and recorded prompt digests allow integrity checks; no model calls are needed to reproduce the reported scores.

The platform is portable to GitHub Pages and uses relative asset paths. The report, interface, and analysis are in English; Turkish experimental prompts remain unchanged. Source code is MIT-licensed; dataset and report are CC BY 4.0.
